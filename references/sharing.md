# 研究室メンバーへの配布と初回利用

このフォルダには制作手順、入力票、CPS LABのスタイルとロゴ、架空研究の通し作例、編集可能な視覚作例、確認方法をまとめている。作成者の過去チャット、個人メモリ、研究リポジトリへのアクセスは不要。

## 導入

1. 共有ZIPを展開し、`SKILL.md`、`references/`、`assets/`、`scripts/`、`agents/` を含む **research-presentation-slides フォルダ全体**を取り出す。SKILL.mdだけをコピーしない。
2. 個人用ならホームディレクトリの `.agents/skills/` の下に置く。最終的に `~/.agents/skills/research-presentation-slides/SKILL.md` となる。Windowsでもユーザーホームの `.agents/skills/` を使う。
3. 研究プロジェクトだけで共有するなら、そのプロジェクトの `.agents/skills/research-presentation-slides/` に置く。個人用とプロジェクト用のどちらかを選ぶ。
4. 同名の既存スキルがある場合は内容を確認し、必要な旧版をスキル検索対象外へ保存してから更新する。同名を複数の検索先に置いて自動的に統合されると考えない。
5. Codexで `$research-presentation-slides` を指定する。変更は自動検出されるが、表示されない場合はCodexを再起動する。

保存先と検出の説明は2026-09-29に[OpenAI公式 Build skills](https://learn.chatgpt.com/docs/build-skills)で確認した。配布先環境の最新案内が異なる場合はそちらを優先する。この作成者の既存導入先では `.codex/skills/` が利用されているが、受取人はその個人環境を再現する必要はない。

## 最初の依頼例

```text
$research-presentation-slides
研究室標準のCPSスタイルで、学会の10分発表を作りたい。
聴衆は情報工学系の学生・研究者。質疑は別に5分。
添付した論文と実験結果が今回の正本です。
まず入力資料を整理し、スタイルと企画書から対話しながら進めて。
```

途中から使う場合：

```text
$research-presentation-slides
添付した企画書とスタイルは確認済み。
今日はアウトラインまで作って。
```

分かる範囲だけ伝えればよい。制作者が [入力票](../assets/input-brief.org) の情報を資料から整理し、次工程に必要な不足だけを確認する。元論文、数値の出典、採用したい写真やデータは各メンバー自身が用意する。

## 工程ごとに必要な能力

| 工程 | 必要な能力 | 利用できない場合 |
|---|---|---|
| 企画書・アウトライン・構成 | 日本語の文章作成、提供資料の読取、ファイル編集 | 読めない資料の箇所を特定し、取得できた根拠だけで下書きを作る |
| 新しいスタイルの抽出 | PPTX/PDFの読取、ページ表示、画像資産確認 | 同梱CPSを選択すれば元PPTXなしで開始できる。新規参照は未確認部分を残す |
| 完成イメージの画像化 | 画像生成／編集ツール | プロンプトまで作成し、画像化は未実施と記録する |
| 編集可能PPTX制作 | 編集可能なPPTX構築・編集ツール、利用するフォント | 原稿と素材を整えてから、対応環境で再開する。画像だけのPPTXへ無断変更しない |
| 最終検証 | PPTXのページレンダー、画像閲覧、ZIP/XML確認 | どこまで確認できたかを記録。全ページ確認を省いて完成と断言しない |
| 実際の登壇動作 | 発表先で使用するPowerPoint等 | アプリでの編集・動画再生などは未検証として引き継ぐ |

このスキル自体はツールの権限、モデル、プラグイン、フォントを追加しない。Codexの `Presentations`、`imagegen`、`load_workspace_dependencies` がある環境では、それぞれの現行手順に従う。PPTX制作の同梱作例コードは `@oai/artifact-tool` を使う。コードを他環境へ持ち込むときは、その環境の実パスと利用可能な版を確認する。個人用の実行パスをコピーしない。

別の環境・制作基盤を使う場合も、[共通完成基準](quality-standard.md) は維持する。利用可能な機能で完成できる範囲と代替の差を記録する。ツールが欠けたまま「同じ環境で確認済み」とは扱わない。

## 初回の品質合わせ

- [通し作例](worked-example.md) で、根拠から主張と図へ変換する方法を確認する。
- [視覚作例](visual-reference.md) のPPTXを開き、文字・図形・表・チャートを編集できるか、自分の環境で表示が崩れないかを確認する。
- 今回の発表の代表ページを作り、同じスタイルの見本と並べて文字階層・余白・図の大きさを比較する。
- 使用したスキル版、制作ツール、取得できるモデル情報、フォント、確認したアプリを制作記録に残す。

全く同じ画像や文章になることを合格条件にはしない。研究資料と発表目的に合わせながら、根拠・論理・可読性・編集可能性の同じ基準を満たす。スキルのZIPを作ることと他者へ送ることは別の操作であり、配布先への送信や公開は利用者が指定した範囲で行う。
