# 説明目的から選ぶレイアウト

章構成とページの型を分ける。各ページで聴衆に理解してほしいことを一つ選び、必要な証拠と読み順から型を決める。写真・UI・出典図・概念イラストを合わせ、本文10枚あたり12〜16点程度を70〜80%のページへ配置することを既定とする。内数のイラストは10枚あたり6〜8点程度、本文の約半数のページへ配置する。[素材要件の数え方](../SKILL.md#写真と研究全体の概要図は必須画像とイラストは標準量グラフは推奨)に従い、問いや表・グラフを中心に見せるページは画像なしでもよいが、本文全体の標準量は保つ。全ページに画像・カード・主メッセージ枠を強制しない。題名が主張を表していれば、副題で同じ文を繰り返さない。

共通枠の実装は [cps.mjs](../assets/layouts/cps.mjs)、構成と書式の初期値は [cps-workshop.json](../assets/profiles/cps-workshop.json) と [cps-midterm.json](../assets/profiles/cps-midterm.json)。以下の型名は生成入力の `type` に対応する。型を選んでも文章量の判断や最終PPTXの全ページ個別目視は省けない。

| 型 | 適した説明・必要な入力 | 配置と意味の判断 | 不向きな場合 |
|---|---|---|---|
| `question` 問い中心 | 研究の問い、必要なら前提や場面を示す画像 | 問いを大きくし、文節で改行。問いだけを受け止めるページなら画像なしでもよい | 同時に複数の結果を説明する |
| `concept` 概念と短い説明 | 定義・知見・仮説・計画の短いブロック、理解を助ける場面・概念の画像 | 画像と短い説明を対応させる。定義を平行な文章で示し、知見と仮説、比較と因果を区別 | 長い方法説明や細かい数値比較 |
| `photos` 写真・図の並列紹介 | 入力が許す画像、名称、短い説明、出典 | 画像の見える高さと説明の開始位置を揃える。原図の場面・試作段階を確認 | 画像がない概念研究、画像の細部が読めない枚数 |
| `table` 表中心 | 長方形のセル行列、列幅、必要なら行高、注目行 | 研究を行にするか比較軸を行にするかを先に選ぶ。単位・条件を見出しやセルへ残す | 一つのセルに長文を入れないと意味が保てない |
| `concept`／`explicit` 実物と役割 | 正本写真と役割説明、必要なら編集可能な仕組み図 | 写真が示す実物と、図が示す抽象的な関係を分ける | 実物がない計画。架空素材を実機写真に見せない |
| `ui` 操作・読み方 | 正本UI、操作または読み方の短い手順 | 重要箇所を読める大きさにし、焼き込み小文字に頼らず説明を外へ置く | UI自体が研究に不要、画面全体を縮めないと収まらない |
| `chart` 結果チャート | 系列・カテゴリ・値・単位・対象・集約単位・証拠区分・解釈 | 個別例と全体集計を同じ粒度で語らない。図下へ解釈を置ける | 定量結果がない研究、図の形に合わせた値の創作 |
| `comparison` 二条件の比較 | 二つの条件名と説明、共通条件・差 | 同じ視覚的重みで並べる。差以外の条件を揃える | 三条件以上を無理に二列へ詰める、比較未実施を結果にする |
| `diagram` 仕組み・分岐 | ID付きノード、接続元・先、方向、矢印の意味 | 図の目的に必要な役割・入出力を区別し、時間・通信・割付・因果を接続データで持つ | 同格の論点を装飾的な矢印で結ぶ、まとめた箱の役割や経路を追えない |
| `toc` 目次 | 構成の章ID・章名・説明 | ページ範囲を最終順から生成。縦目次か2×2かは構成に従う | 手入力の範囲を固定したまま並べ替える |
| `summary` サマリ | 要点、著者情報、指定連絡先、必要なら議論の問い | 本編末尾と補足後の最終表示を別に選ぶ。持ち帰る要点を優先 | 本編で述べていない新しい結果を出す |
| `divider` 区切り | 章名・案内文、または補足の開始 | 余白を確保し、本文と同じ密度を求めない | 短い発表へ構成上不要な扉を増やす |
| `cover` 表紙 | 今回の題目・著者・発表条件、選択した型の素材 | 本文プロファイルから独立。動画と編集可能な文字を分ける | 参照例の著者・素材の流用 |
| `explicit` 個別構成 | 上記部品の組合せと座標・役割 | 複数の証拠を同じページで対応させる必要があるときだけ使用。共通枠と検査を維持 | 問題のある既定値を全ページの例外座標で隠す |

## 役割と入力の最小単位

- 文字は `title`、`body`、`question`、`header`、`label`、`source`、`page` 等で役割を付ける。図のノードと辺、表、チャート、画像も識別できるIDを持つ。制作メタデータを可視文へ混ぜない。
- 表はセルの文章、列幅、必要な行高、強調対象を入力する。列幅の合計は表全幅、指定した行高の合計は表全高へ合わせる。`padding_in` でセル内余白を調整し、出典の領域を確保する。
- 画像はパスと説明、必要な見せ方を入力する。正本を保持し、原寸・配置寸法・実効解像度・利用条件を記録する。SVG等の制作元と埋込用の派生画像は素材台帳で対応させ、PPTX上で編集できる範囲と区別する。
- 図は接続元・先のノードID、方向と意味を持つ。座標だけから関係を推測しない。全体像なら内部機能をまとめてよいが、経路の説明に必要な役割・入出力が隠れる場合は分割やラベルを選ぶ。矢印の意味が混在して読み取れない場合だけ、短いラベルや凡例を画面へ置く。意味の記録と可視ラベルは別に扱う。
- チャートは値だけでなく、対象、単位、分母、集約単位、実測／例示／計画等を持つ。根拠のない定量図を計画の飾りにしない。
- 各主張は入力の所在と結び付ける。数値や引用を使う主張では元資料の対象と、該当する標本数・集約単位・期間を照合し、全体と部分集団を取り違えない。短文化しても対象を広げず、知見・解釈・仮説・計画を区別し、省くと結論が変わる条件を画面に残す。

## 収まらない場合

まず意味の重複を減らす。次に型、余白、列幅・行高、文節での改行、画像と文の比率、素材の選び方を直す。詳しい方法・追加の限定はメモや補足へ移せるが、主張の根拠・必要条件・出典は落とさない。複数の主題があるならページを分ける。標準量から画像を減らすのは使用者が指示した場合だけとし、短い発表や可読性、制作時間、ツール・素材の不足を理由に自動で減らさない。点数合わせの装飾は加えず、未解消の不足は記録する。採用した文字サイズ範囲外への縮小、表やチャートの画像化、全面画像化を救済策にしない。

修正を入力・共通部品・コードへ戻して再生成し、同じ不具合が残らないことを最終ファイルから確かめる。単発のPPTX座標修正を完了形にしない。

## 作例の使い分け

[従来の9枚](visual-reference.md) は `cps-midterm` の表紙・目次・章扉・図表・まとめの比較教材。[通し作例](worked-example.md) は根拠から構成までの判断を示す。短い研究発表の入力と再生成は [generation.md](generation.md) を参照する。作例の題目・著者・数値・文献・画像を新しい研究へ転用せず、型を選んだ理由だけを引き継ぐ。

| 作例のページ | 選んだ型と理由 |
|---|---|
| 短い記録方法：3 | `question`。短い変化という問いそのものを中心にする |
| 同：4 | `table`。候補規則と保持・欠落・必要な証拠を行ごとに対応させる |
| 同：5–6 | `photos`／`ui`。概念素材の役割を並べ、操作の要点は画像外の編集可能な文字へ出す |
| 同：7 | `diagram`。処理選択の接続をID付きの辺で表し、因果効果と混同しない |
| 同：8 | `chart`。一つの合成系列と保持表現を比較し、単位・対象・解釈を画面へ残す |
| 同：9–10 | `comparison`／`summary`。未実施の評価条件を同じ重みで比較し、合成例の範囲で締める |
| 研究計画：3–4 | `question`／`table`。問いと概念の違いを示す。この固定入力には写真・実機・定量図を含めていない |
| 同：5–7 | `concept`／`comparison`／`summary`。調査の計画、同意の二つの場面、未実施という範囲を示す |

これらは固定入力の教材であり、実際の制作で写真を省いたり画像・イラストを標準量から減らしたりする根拠にはしない。新しい発表では[写真と研究全体の概要図の必須条件、画像とイラストの標準量](../SKILL.md#写真と研究全体の概要図は必須画像とイラストは標準量グラフは推奨)を満たし、適したデータがあればグラフも検討する。
