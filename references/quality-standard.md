# 研究室共通の完成基準

## 判定の仕方

過去のチャットの読み込みや作成者の追加指示に頼らず、ここに示す観察可能な基準で確認する。研究内容の強さとスライドの制作品質は分ける。予備的・否定的な結果でも、その範囲を正しく伝えられれば制作上の基準を満たす。

各項目を `pass`（確認して合格）、`error`（確実な不具合）、`review_required`（判断待ち）、`unverified`（解析・表示・操作が未確認）、`not_applicable`（理由付き対象外）で記録し、根拠のファイル／スライド番号を添える。点数の平均で問題を相殺しない。判定を良くするために基準や事実を書き換えない。必須項目の error、未解決の review_required、unverified が残れば「検証済み完成」としない。制約のある候補を渡す場合は、どの条件を満たしていないか明示する。

## 工程ごとの到達点

| 工程 | 確認すること | 合格の根拠として残すもの |
|---|---|---|
| スタイル | 表紙・章扉・本文・結果の文字階層、色、余白、ロゴ、フッターが定義されている。文字サイズと座標の単位を区別している | 今回のスタイルと代表ページ。元参照との差分があれば記録 |
| 企画書 | 現状から今回の障害へ絞れ、作戦と成果が対応し、結論が結果の強さを超えていない | 作戦↔結果↔教訓の対応、主要主張と根拠の所在 |
| アウトライン | 話題列で抜けを、メッセージ列で論理を読める。各MBは1主張、3項目。主結果と副次結果の重みが適切 | 話題／メッセージの通読結果、時間配分案、本編／補助の理由 |
| 構成と図 | 本編MBの対応先がある。図は要素・矢印の意味・個数・配置・素材・作成方法が具体的 | MB↔スライド表、図の仕様、出典と入力データ。表紙等の例外を区別 |
| 画像化 | 1枚の一覧画像に表紙からデッキ末尾まで全ページが収まり、最新構成と同じ枚数・順序・番号。見た目の方向性が分かり、実測を装う生成図がない | プロンプト、入力と出力画像、対応版、欠落／重複／切れの確認 |
| PPTX | 確定した内容と見た目を再現。全ページを読め、要求した要素を編集できる | 完成PPTXの構造検査、全ページの個別レンダー確認、編集可能性の根拠 |

企画書・アウトライン・完成イメージの各現行版について、使用者レビューと了承の記録が必要。修正後は再レビューする。特定工程を明示的に省略する本人指示がある場合は、その対象と基準版を記録する。技術的な検証合格や別エージェントの評価だけではレビューを代替できない。

固定入力・架空作例による開発内部試験では、利用者レビューを実施したと書かず、対象外の理由と固定入力を記録する。新しい実研究の制作と混同しない。

作成者の確認と、利用者の内容確認は別に記録する。利用者が先へ進むよう指示していても、誤値・欠落・壊れたファイル等の修正は済ませる。変更が研究上の判断を必要とするときは具体的な案を提示する。

## 内容と論理

- 主要主張の出典が存在し、該当箇所を実際に確認できる。先行研究と自分の結果、実装済みと予定を混同していない。
- 数字は元データと同じ単位・分母・期間・条件を持つ。集計や変換をした場合は式またはコードを残す。
- 手法で測っていないことを結果として述べない。限定条件での動作から一般的な有効性・優越性へ飛躍しない。
- 方法と結果を対応させ、結論で初めて新しい結果を出さない。1つの結果を言い換えて複数の貢献に水増ししない。
- 専門語は聴衆に必要な説明を置き、略語を未定義のまま主要メッセージに使わない。必要以上の否定文や免責文で主張を埋めない。
- 導入の重要語・判断対象に必要な前提があり、研究が誰に何をもたらすことを目指すか早い段階で伝わる。先行研究の結果から今回の問いへの接続に飛躍がない。問い・移行・章内要約を追加した場合は、各ページの役割が重複していない。
- 持ち時間に対する配分は提案と実測を区別する。実際の読み上げ・リハーサルを行っていない場合、「時間内に話せた」と書かない。

## 見た目と図の意味

- 採用した構成・プロファイルと実際の目次・章順・章扉・本編終了・補足が対応している。`cps-midterm` は4章・2×2目次・縦4行まとめ、`cps-workshop` は可変章数・縦目次・選択した章扉とサマリ位置を照合する。スタイルで決めた位置・文字階層・色の役割を、代表ページと全体一覧で比較する。独自の装飾やカード部品を途中で増やさない。
- 最終ファイルからレンダーした**全ページ**を個別に見る。一覧だけで小さいラベル、語中改行、文字欠け、句読点だけの行、図の切れを合格にしない。
- 描画エンジンと版を記録する。1.5.0の最終表示確認ではPowerPoint 16.111のPDF書出しと `pdftocairo` を使った。画像全体の読み取りで欠けに見える箇所は、同一画像の該当領域や画素・文字抽出も確認し、見落としから描画不具合を断定しない。冗長な段落書式の整理を表示修正の証拠にせず、対象の最終PPTXを描画する。PDF書出し、反復操作の安定性、ネイティブ要素の実編集、動画再生は別の検証。
- 本文・図ラベルを今回のスタイルのサイズで読める。収まらない場合は短文化・補足移動・構成変更を優先し、無断で文字を縮めない。
- 接続線が意図した要素へ届き、分岐が完結している。並置・比較を通信や因果の矢印として描かない。
- 図の値・軸・単位・比較関係を正本と照合する。まず主張や図ラベルを正確にし、比較条件・対象・集約単位など解釈を変える情報を画面にも示す。詳しい方法と追加の限定はメモに記録する。
- 写真・スクリーンショットは用途が分かる切り抜きにし、縦横比を崩さない。図の出典は必要な粒度で表示する。
- 追加イラストは参照にした既存画像と線・塗り・人物の描写・陰影が揃う。並列項目へ不要な接続や序列を付けていない。先行研究の原図は示す場面が確認され、後続の比較表の対象と対応する。
- 標準の中間発表型では同梱作例の目次・章扉・通常ページ・まとめを見比べる。表紙だけ選んだ表紙タイプA／表紙タイプBと比較し、本文へ旧型を持ち込まない。作例の研究テーマ・数値・枚数は継承しない。実案件の納品時には、作例にある未提供写真・動画・目次画像の配置枠を残さない。

## 編集可能性とファイル

| 要素 | 必要な確認 |
|---|---|
| 見出し・本文・注記 | 文字として保存され、表示だけの画像になっていない |
| 正確な模式図 | 図形・接続線・文字を個別または意味単位で編集できる |
| 表 | セルと文字を編集できる。単なる表の写真でない |
| チャート | 新規作成は正本データによるネイティブチャート。既存の出典画像を使う場合は出典と編集できない範囲を明示 |
| 写真・概念イラスト | 画像として配置してよい。隣接する説明文まで平坦化しない |
| 既存のユーザー編集 | 指定された修正以外のテキスト、配置、ノート、媒体を保持。原稿を更新した場合は既存段落を移動先も含めて照合し、派生物の手修正も保持 |

`scripts/check_pptx.py` はPython標準ライブラリだけでZIP、XML、参照、スライド順と数、各ページの文字・図形・表・チャート・ノート等を点検する。実際の見た目、意味、PowerPointでの操作・再生の代わりにはならない。既存制作基盤の検査と併用する。

```bash
python3 <スキル>/scripts/check_pptx.py <完成PPTX> --expect-slides <予定枚数> --report <作業先>/pptx-check.json
```

表紙型の選択と素材を記録する。表紙タイプBの動画では静止ポスターと、自動再生・ループ・無音・次ページ遷移時の停止を確認し、確認できない動作は未検証にする。対象のPowerPoint等で開いて編集・再生まで確認した場合は、そのアプリと環境を記録する。確認できなかった場合は未検証として残す。スキルの作例を生成できたことを、新しい研究発表の全ページ検証へ代用しない。

## 修正とレビュー

修正優先度は、事実・根拠 → 論理 → 図の意味 → 読める配置 → 装飾。誤った結論を目立たせるデザイン改善は行わない。

初めてこのスキルを使うメンバー、研究の主張を大きく変えた発表、全体を新規制作したPPTXでは、利用可能なら別エージェントに**実際の成果物と元資料**を読ませる。元の自己評価を渡さず、具体的な欠落・飛躍・読めない箇所を確認する。外部サービスへ勝手に送信しない。委任できない場合は同じ基準で別の確認パスを行い、その方法を記録する。

各工程で必要な項目だけを制作記録に残す。[検証記録のひな形](../assets/quality-review.org) は最終確認時の補助として使える。毎回全欄を埋めるために不要な工程を増やさない。

画像素材の新規生成・編集は、用途・必要情報・品質に適した手段を実際に使えたか、制作手段・入力・出力の記録で確認する。未生成・未閲覧を完了にせず、生成した概念素材を写真や測定記録の実証資料と混同しない。既存素材の利用、PPTXネイティブ要素、完成イメージの使用者レビュー、表示検証用レンダーは区別して記録する。

- 冒頭に目次があり、本文の章名・順序と一致する。短時間を理由に省略していない。
- 表紙を含む全スライドの右下に、表示順1からデッキ末尾まで連番があり、欠番・重複がない。番号は編集可能な文字で、最終レンダーでも読み取れる。動画表紙では動画より前面にあり、再生中の可読性も確認する。

- スライド構成ファイルに目次・採用した全章扉が独立項目として存在し、本文と同様に番号・内容・配置・素材を記載している。目次の章名・順序と、各章扉・本文・まとめが一致する。

- 初回に制作の流れと3回の必須レビューをチャットで案内し、各成果物の提示時には実際のリンク／画像・確認点・回答方法・了承後の次工程を伝えている。ガイダンスを表示しただけでレビュー完了とはしない。

- 工程が進むほど強い推論モデルを勧める方針を案内している。モデル変更を必須条件や品質保証にせず、使用者の選択と実際に確認できた設定を区別している。

- 完成イメージ・PPTX作成前に任意の参考スライドを案内した。提供時は実際のページを確認し、CPS LABの基本と、参考へ寄せた細部を区別して記録・反映している。PPTX直前の追加参考で見た目が変わった場合は、更新した一覧画像への再レビュー・了承がある。

- ベース・メイン・独立したアクセントのHEX値と用途が定義され、スタイル・構成・完成イメージ・PPTXで一致している。ボタニカのアクセントは #38761D、他のCPS配色は対応表に従う。通常文字と強調箇所を区別し、使用する背景とのコントラストを確認する。

- 下端横線のあり／なしが使用者の選択と一致し、構成・完成イメージ・PPTXで統一されている。ありの場合はメインカラーを使い、なしでもロゴ・ページ番号を消していない。章扉・表紙タイプBは元の線なしを保つ。

- 表紙以外の左上に章名／ページ種別、右上に短縮発表タイトルが小さく表示され、本文・章扉ロゴと重なっていない。
- 引用番号と同じページ下部の参考文献、台帳の出典が一致する。連番引用と非連番引用を区別し、ノートだけに出典を隠していない。引用がないページへ架空の文献を追加していない。
- 採用した本編終了／デッキ末尾のサマリに概要・著者・所属・使用者が表示を指定した連絡先がある。省略指定も守り、連絡先を推測していない。全ページ一覧にも採用したサマリが含まれる。

## 発表用メモの確認

- まず主張・タイトル・図ラベルを根拠に合う短い表現へ直す。対象・分母・単位・比較条件・実測／例示／計画など、省くと結論の理解が変わる情報は必要なページの画面にも読める形で残す。詳しい方法、追加の限定、想定質問への長い回答は発表用メモへ書く。同じ条件を全ページへ機械的に追加しない。画面の主張は根拠の強さと整合している。
- メモはUTF-8のプレーンテキストで、出力PPTXと同じディレクトリにある。スピーカーノートだけで代用していない。
- 最終の表示ページ番号・スライドID・題名・画面の主張に対応し、口頭で伝える補足・限定と根拠が追跡できる。利用者の追記を保持している。
- 対象・分母・単位・実測／例示／計画など、理解を変える条件が画面から消えていない。長い補足だけをメモへ移し、メモの場所を納品時に案内している。

## 最終受入の11項目

検証対象のPPTXのSHA-256、入力正本とその版、レンダー出力を同じ記録に結び付ける。修正後は再生成したファイルへ検証を更新する。

| ID | 合格条件 | 証拠 |
|---|---|---|
| Q1 内容 | 主張・数値・条件・引用が入力と一致し、実測・例示・仮説・計画を区別 | ページ／主張IDと入力の対応 |
| Q2 構成 | 章・目次範囲・本編終了・補足・可視番号が採用構成と一致 | 構成データと最終PPTX |
| Q3 可読性 | 全ページに欠け・読めない改行・意図しない重なりがない | 最終PPTXからの全ページ個別画像と確認記録 |
| Q4 視覚仕様 | 採用した色・枠・文字階層・余白と、説明に適した型 | プロファイル・要素の役割・比較画像 |
| Q5 図の意味 | 接続・方向・単位・分母・対象・集約単位が正しい | 図構造・データ・元資料 |
| Q6 編集可能性 | 要求した文字・表・チャート・正確な図がネイティブ | 要素検査。対象アプリの実編集は別記 |
| Q7 再生成 | 入力・部品・コードへ戻した修正が再生成後も維持 | 同一入力の再生成物と検査 |
| Q8 汎用性 | 異なる説明方法の研究と従来型で必須項目を満たす | 複数の架空作例・日本語・計画中心入力と反復生成 |
| Q9 動作 | 要求された動画・リンク等が対象アプリで機能 | アプリ・版・実際の操作結果。静止画から推定しない |
| Q10 配布 | ファイル・相対リンク・版・manifestが整合 | 配布検査ログ |
| Q11 独立性 | 配布一式と当該入力だけで生成でき、他研究・他人の情報が混入しない | アクセス可能資料の記録・出典対応・独立生成物 |

Q11の確認では、単に作業先を変えたことを隔離と呼ばない。参照可能なファイル・会話・ネットワーク・任意の参照を記録する。改修に用いた実研究PPTX・抽出物・診断・修正済みの答えにアクセスできない条件を用意できなければ、独立試験は未検証とする。既知固有語の検索だけでなく、題目・著者・連絡先・引用・値・素材が当該入力に由来するか照合する。

実務指標は、利用者のPPTX直接修正回数、配置を救済する追加指示回数、初回候補の重大不具合、内部修正回数、独立生成での再発を別々に数える。直接修正・救済指示の目標は0回。内部修正回数だけを減らして品質を犠牲にしない。「参照と同等」は検証した課題・環境・項目に限って報告する。
