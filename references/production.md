# 構成・画像化・編集可能なPPTX

## スライド構成と図の検討

使用者のレビュー・了承を受けた現行版アウトラインとスタイルを読み、各MBを1枚へ対応させる。本編の `S01` などのスライドIDとMBの対応を記録する。標準は選択した表紙、画像付き2×2目次、4章の上部型章扉と内容、縦4行のまとめ、必要な補足、最終サマリの順。第1章に関連研究の個別紹介と比較を置く。表紙・目次・章扉・まとめ・最終サマリの枚数は内容MBと区別し、本編と補足も別に数える。1MBを分割したい場合は先にアウトラインを直すか、ユーザーが認めた例外として記録する。

### 目次・章扉も構成ファイルに記載する

`slide-structure.org` には、表紙・目次・採用する各章扉・本文・まとめ・補足・最終サマリの全スライドを、実際の表示順で1枚ずつ独立した見出しとして記載する。「目次を追加」「適宜章扉」とだけ書いたり、スタイルファイルへの参照だけで済ませたりしない。本文のMBに対応しないページは「対応MB：対象外」とし、架空のMBを増やさない。

以下の `TOC-01`・`DIV-01` は内部IDの例。既存ID方式がある場合は維持し、表示ページ番号とは区別する。番号・章名・画像パス等の記入欄は実際の内容で埋める。素材が未作成なら生成する画像の内容・ImageGenによる制作予定を明記し、採用後に実在パスへ更新する。

#### 目次の記入ひな形（必須スライド）

```org
** TOC-01 目次
- 種別 :: 目次
- 表示ページ番号 :: 実際の表示順の番号（表紙直後なら2）
- 対応MB :: 対象外
- タイトル :: 目次
- 全体案内文 :: この発表の流れを示す短い一文を記入
- 掲載する章と画像 ::
  - 左上：01 研究のねらい／画像の内容・採用ファイル・出典を記入
  - 右上：02 しくみと評価方法／画像の内容・採用ファイル・出典を記入
  - 左下：03 ここまでの結果／画像の内容・採用ファイル・出典を記入
  - 右下：04 今後の展望／画像の内容・採用ファイル・出典を記入
- レイアウト詳細 :: 上部にタイトルと案内文、下部に2×2配置。章番号・章名・画像の位置と大きさ、中央の薄い縦横線、余白を今回の数値で記入。
- 作成手段・素材 :: 文字・区切り線はPPTXネイティブ要素。画像は正本素材またはImageGen。計画画像には「計画」と表示。
- ロゴ・フッター・番号 :: 下端横線は今回の選択（あり／なし）を明記。左下ロゴ、右下に必須の表示ページ番号。
```

章名・順序は今回の確定アウトラインに合わせ、本文・章扉・まとめと一致させる。

#### 章扉の記入ひな形（採用する各章について記入）

```org
** DIV-01 第1章の章扉
- 種別 :: 章扉
- 表示ページ番号 :: 実際の表示順の番号を記入
- 対応MB :: 対象外
- 章番号 :: 01
- 章名 :: 研究のねらい（今回の確定章名を記入）
- 案内文 :: この章で何を伝えるかを一文で記入
- レイアウト詳細 :: 上部のキーカラー帯に章番号・章名、その下に案内文。帯・文字の座標、寸法、文字サイズと色を今回の値で記入。下部は広い余白。
- 作成手段・素材 :: 帯・文字はPPTXネイティブ要素。右上ロゴの実在パスを記入。画像を使う場合は内容・配置・作成手段も明記。
- ロゴ・フッター・番号 :: 右上ロゴ、左下ロゴと下端線なし。表示ページ番号は右下。
```

第2章以降も省略せず1枚ずつ記載する。短時間発表で章扉自体を省く場合は、構成ファイルに対象章と理由を記録し、存在しないスライドへページ番号を割り当てない。目次は省略しない。

完成イメージ・PPTXへ進む前に、構成ファイルだけで全ページの順序・番号・内容・図や画像の配置を把握できるか確認する。目次や章扉を後から追加・削除したら表示番号と全体枚数を更新し、影響を受ける完成イメージも更新して使用者レビューを受ける。

本文スライドの標準仕様：

```org
** S01 現状
- 種別 :: 本文
- 左上の小見出し :: 現在の章名
- 右上の小見出し :: 記録済みの短縮発表タイトル
- 本文／図の引用番号 :: 使用する [1]／[1-4] 等と該当箇所
- ページ下部の参考文献 :: 引用番号と対応する短い書誌情報（引用なしなら対象外）
- 表示ページ番号 :: 実際の表示順の番号を記入
- 対応MB :: MB-01
- タイトル :: 話題が伝わる短い表現
- メインメッセージ :: 聴衆へ伝える答え
- 載せる内容 :: 図表、短い補足、必要な条件や出典
- 図形・図表の詳細 ::
  - 要素、個数、形、大きさ、色、配置、整列、余白。
  - 矢印が表す意味、強調する箇所、図に含めない関係。
  - 写真の実在ファイル、見せる範囲、切り抜き、キャプション。
- 作成手段・素材 :: ImageGen（画像の生成・編集）／PPTXネイティブ図形・チャート・表／既存の正本画像。
```

口頭説明・出典詳細・制作者への注意は別に記録する。上部に話題とメッセージ、下部に補足や図表を置く中間発表型を使う。章扉は上部の章番号・章名・案内文と右上ロゴ、まとめは左の章名と右の要約を4行にする。旧来の下寄り章名帯や、まとめの下部の大きな結論帯へ戻さない。同じ図を段階的に見せる場合は縮尺と位置を保ち、既出箇所の灰色化・囲み・注記で読み順を示す。

表紙仕様は [cps-lab-style.md](cps-lab-style.md) の `fit`／`midterm` を参照する。中間型で必要な動画が未提供の場合は、素材の指定または静止画への変更を利用者に確認し、静止見本を動画入り完成品と呼ばない。表紙の選択で本文や章構成を切り替えない。

### 図の作り分け

| 対象 | 基本の手段 | 注意点 |
|---|---|---|
| 利用場面、概念イラスト、外観構想 | ImageGenや適切な既存画像 | 計画図と実証写真を区別。正確な文字はPPTXで重ねる |
| 通信、処理、比較、個数、位置関係 | 編集可能なPPTX図形・線・文字 | 意味単位でグループ化。矢印が因果を過剰に示さないようにする |
| 実験結果、定量図 | 正本データから作るネイティブチャート | 値・軸・単位・標本・誤差表現を照合。ImageGenで作らない |
| 比較表、評価表 | ネイティブ表 | 文字とセルを編集可能にする。出典や比較の意味を保持 |
| 実機、実験場面、UI | 正本写真・スクリーンショット | 生成画像で実証資料を代用しない |

画像の新規生成・編集は常にImageGenを使う。D2等の別ツールやコードによるSVG/PNG生成・加工へ切り替えない。画像素材としての模式図はImageGen、編集可能な要素としての模式図はPPTX図形で作り、後者を画像として書き出して代替しない。定量図はネイティブチャートとし、入力データを保存する。画像制作・既存素材・PPTX実装・検証レンダーの区別は [画像制作のルール](../SKILL.md#画像制作はimagegenを使う) に従う。

### 素材管理

採用素材を `slide-assets/` へ必要な分だけ集める。原本は保存し、固定コピー・加工済み派生物・論文等からの抽出画像を区別する。既存台帳があればその形式を使う。新規台帳には以下を記録する。

- 素材ID、保存先、コピー元または出典、使うスライド。
- 原本との関係、トリミングや匿名化などの加工、寸法、利用条件。
- ファイルのSHA-256。固定コピーならコピー元と一致を確認する。

既に加工済みの画像を、未加工の撮影原本と呼ばない。写真で特定の情報を除去する必要があるときは、見かけ上のクロップや覆いだけで済ませず、PPTX内部に元画像が残るか確認する。既存の利用許諾は保持し、毎回一律に聞き直さない。

## 完成イメージの画像化

作成前に任意の参考スライドを案内する。提示された資料を実際に見て、CPS LABの基本を保った細部調整をスタイルと各ページ仕様へ反映する。案内・受付・再レビューは [使用者へのガイダンス](../SKILL.md) に従う。

画像化の依頼では、現行 `imagegen` スキルを読み、ImageGenを使う。利用できない場合は画像制作を停止し、別ツールで代替しない。「プロンプトだけ」の依頼なら生成せず、すぐ貼り付けられるプロンプトを納品する。画像化まで依頼されていればプロンプトを示すだけで終了しない。

ユーザーが指定した最新構成を基準に、ページ番号・順序・枚数・図案・スタイルをプロンプトへ反映する。完成イメージの成果物は、全ページを表示順に一覧できる1枚の画像とする。表紙・目次・採用する各章扉・本文・まとめ・補足をすべて含める。代表ページのみの提示や複数の分割一覧では代用しない。各スライドを16:9に保ち、左から右、上から下へ並べる。構成の総枚数に応じて行列数と画像サイズを選び、全ページが欠けずに入るようImageGenへ指示する。ページ番号を表示し、空きセルを架空のスライドで埋めない。

プロンプトに含める要素：

1. **目的**：編集可能PPTXを別途制作するためのデザインラフ。
2. **参照**：確定スタイル、正本ロゴ、提供された図・写真、任意の参考スライド。CPS LABとして保つ要素と、参考へ寄せる文字組み・配色・図の大きさを区別して指定する。
3. **共通仕様**：比率、背景、色、文字階層、左上の章名・右上の短縮タイトル、引用番号と下部文献、最終サマリ、ロゴとフッター、下端横線の選択（FOOTER_LINE）、余白。線なしでもロゴとページ番号を保持する。
4. **一覧仕様**：実際の総枚数、読み順、行列数、各ページの比率、未使用セルは空白、番号。
5. **各ページ**：タイトル、主メッセージ、主図、配置の狙い。
6. **画像で重視すること**：全体のトーン、余白、情報階層、図版配置、反復表現、ページ間の統一感。
7. **生成上の制約**：正面の平面スライド、切れ・欠落・重複・入替を避ける。内部IDや制作指示を聴衆向け画面へ出さない。未提供の実証資料を捏造しない。

図のラベルや細かな日本語本文はOrg正本で保つ。ロゴを画像生成が正確に描いたとみなさず、最終PPTXには正本画像を配置する。生成後に枚数・順序・番号・比率・空白セル・端の切れを確認し、問題があれば再生成／編集する。画像の編集にも常にImageGenを使う。

細部の確認用に個別画像を追加することはできるが、必須レビューの対象は全ページを収めた1枚の一覧画像とする。枚数が多く一度で欠けなく生成できない場合も、ImageGenで修正・再生成する。単一画像で全ページを確認できる状態にできなければ制約を伝えて停止し、分割版だけで了承済みとしてPPTX制作へ進まない。別の画像加工ツールで合成して代替しない。

プロンプト、実際の入力画像、出力した一覧画像のパス・総ページ数・行列数、対応する構成の版を記録する。画像が存在しない場合に「画像化済み」「確認済み」としない。上流変更後の古い一覧は見た目の参考に限り、枚数や本文の正本にしない。

## 編集可能なPPTX制作

制作前に参考スライドの追加・変更を任意で受け付ける。既存参考は引き継ぐ。新しい参考で了承済みの見た目が変わる場合は、完成イメージを更新して使用者の再レビュー・了承を受けてから制作する。

### 実行環境

現行 `Presentations` スキルの実装・テンプレート参照・検証の手順を読む。`load_workspace_dependencies` でNode/Python等の実際のパスを取得する。古いキャッシュのバージョン番号をこのスキルからハードコードしない。

現在の制作基盤はJavaScript ES modulesと `@oai/artifact-tool`。実装API、制作開始の記録、finalizer等はインストール済みPresentationsスキルに従う。APIを推測せず、現行リファレンスを読む。データ計算とPPTXのネイティブチャート実装を、画像生成と混同しない。

必須ツール・ランタイムが使えない場合は、依存しない原稿・図仕様・素材整理を完成させ、欠けている能力を具体的に伝える。新規タスクの作成や別製品への切替を無断で行わない。代替手段で要求を満たせる場合は、その差と制約を明示する。LibreOfficeを使うなら依存関係ツールで解決した同梱版を使い、ユーザーのデスクトップ版へ切り替えない。委任時も同梱版の実パスと条件を伝える。

### 実装の正本と編集可能性

- 研究内容・文字・数値：今回の確定資料と構成。
- 配色・配置：今回のスタイルと確認済みラフ。
- 編集対象の現状：ユーザーの最新PPTX。添付版と同名のローカル版が違えば指定された版を優先する。

ラフ画像をスライド全体へ貼って済ませない。本文・見出し・ラベル・模式図・表をネイティブ要素で作り、意味単位でグループ化する。正本写真・既存の出典図・ImageGenによるイラストは画像素材として配置する。新規の定量図はネイティブチャートにする。出典の短い表示とノートの詳細を対応させる。

既存PPTXへの追加・修正では、対象以外の本文・配置・図・ノート・動画・補足統合を保持する。古い全体生成スクリプトから作り直して手動編集を消さない。部分編集が技術的にできない場合は、忠実性を検証できる方法を準備するか、制約を明示して判断を求める。

### 検証と納品

まず作業用ディレクトリに候補を作り、以下を確認する。

1. **内容**：全スライドの対応、順序、本編／補足枚数、可視テキスト、数値・条件・出典。作りかけ表示や制作指示が残っていないか。
2. **ファイル**：ZIPとメディアの整合、参照・リンク、フォント、スライドとノートの対応、ネイティブ要素の存在。現行Presentationsのfinalizerも通す。
3. **見た目**：出力PPTXから全ページを再レンダー。一覧で統一感、各ページで重なり・切れ・改行・ラベル・余白・図の意味を確認する。タイトルや本文を縮める前に内容と配置を整理する。
4. **動作**：動画・アニメーション・リンク等が要求された場合は対象環境で別に確認する。静止画レンダーを再生検証と呼ばない。PowerPointで実際に確認した場合だけそう報告する。

表示の欠けがあればフォントや配置を点検し、PPTXを修正して再レンダーする。定量図を別ツールでPNGへ変換して回避しない。画像素材自体の修正にはImageGenを使い、正本との忠実性を確認できなければ問題を記録して止める。

正式納品先は1つにし、検証候補と旧版を `.private/` 等の作業先に置く。既存ファイルの更新が指示されている場合は、別名の検証済み候補を作ってから正式パスへ反映する。finalizerの上書き禁止を回避するために元PPTXを先に消さない。新規作成・別版の依頼なら元ファイルを保持する。

最終的にPPTXと、用途に必要な再生成コード・図表入力・素材の場所を示す。PDF、発表原稿、想定質問集は依頼された場合に作る。未解決の表示・編集上の制約だけを明確に伝え、準備完了を制作完了と言い換えない。

## 完成イメージからPPTXへ進む条件

全ページを一覧できる1枚の完成イメージ画像を使用者へ提示し、現行版へのレビューと了承を受けるまでPPTX制作を開始しない。修正依頼には画像を更新して再提示する。画像が未生成、レビュー未回答、修正版が未了承なら「確認待ち」のまま停止する。一括制作の依頼や内部検査で省略しない。詳細は [必須レビュー](../SKILL.md#対話と再開3回の必須レビュー) に従う。

## 目次とページ番号の必須確認

構成に必ず目次を含め、内部IDとは別に全スライドの表示番号を記録する。ImageGenの完成イメージにも番号を指示し、生成画像の欠け・重複は修正してから使用者レビューへ出す。PPTXでは表紙から最終サマリまで1始まりの連番を右下の編集可能な文字で実装し、最終表示順と照合する。中間型表紙も省略せず、動画より前面に置く。

## 小見出し・引用・最終サマリを構成に記載する

本文だけでなく目次・章扉・まとめ・補足・最終サマリにも、左上の章名／ページ種別と右上の短縮発表タイトルを記載する。全ページの引用欄を確保し、各ページへ「引用番号・該当する主張／図・ページ下部の文献」を具体的に記録する。引用なしなら対象外と記録してよく、文献を捏造しない。

引用台帳に、文献番号、引用キー（あればBetter BibTeXキー）、確認済みの書誌情報、短い表示文、使用スライドを記録する。引用番号とページ下部の文献、ノートの詳細、入力資料の対応を確認する。連続していない出典を [1-4] とまとめない。

```org
** END-01 最終サマリ
- 種別 :: 最終サマリ（補足を含むデッキの最終ページ）
- 表示ページ番号 :: 実際の最終番号
- 対応MB :: 要約元のMBを記入
- 左上の小見出し :: サマリ
- 右上の小見出し :: 短縮発表タイトル
- 正式題目・著者・所属 :: 今回の正本の表記
- 発表の概要・持ち帰り事項 :: 確定した内容を2〜4点で要約
- 著者の連絡先 :: 使用者が指定したメール／URLと表示の確認
- 引用番号・下部参考文献 :: 使用する文献と番号（なければ対象外）
- 配置 :: 上部に題目・著者、中央に概要、下部に連絡先。今回の具体的な寸法と文字サイズを記入
- 作成手段 :: 文字・リンクはPPTXネイティブ要素
- ロゴ・横線・ページ番号 :: CPS LABの正本ロゴ、選択済みの横線設定、右下の必須番号
```

最終サマリを全ページ入りの完成イメージに含めてレビューする。4行まとめと統合した場合はその合意と含めた要素を記録する。
